# CampusCircle 开发路线

> 最后更新：2026-08-09。本文只描述当前产品基线与后续工作，历史的“讨论进展”原型不再作为业务功能或前端入口。

## 1. 当前产品基线

CampusCircle 是按高校校区组织内容的校园社区。用户绑定校区后，可在同校区、同校、10 km、20 km 或同市范围发现帖子；通知、详情、评论、点赞与个人主页则可直接访问已经获知的内容，不受 Feed 范围切换影响。

当前已完成：

- 账号、短期 Access Token 与 HttpOnly Refresh Token 续期；
- 高校、校区、地理范围与附近学校缓存；
- 帖子、评论、二级回复、点赞、通知、删除确认和内容跳转；
- 个人主页、头像上传压缩、资料设置、校园切换次数限制；
- Redis 热榜、浏览量批量落库、缓存故障降级；
- Transactional Outbox、RocketMQ 可选投递、通知幂等；
- 问题追踪：发起、订阅、候选答复、通过/无效、完成、重新开启、删除与订阅通知；
- 评论问题聚合：批量读取评论问题摘要、评论旁状态入口、帖子内集中展示，以及帖子作者“作者”身份标签；
- RAG v1：权限过滤、ES 异步索引、Embedding、关键词检索、向量检索、RRF 融合和 SQL 降级；
- Vue 3 前端、Docker Compose 本地运行与后端自动化测试。

## 2. 当前系统边界

```text
浏览器
  -> Vue 3 / Axios
  -> Spring Boot API
      -> MySQL 事实数据
      -> Redis 缓存与会话
      -> Outbox / RocketMQ 异步事件
      -> Elasticsearch 检索投影
      -> OpenAI-compatible chat and embedding providers
```

写操作以 MySQL 事务为准。缓存、消息和搜索均允许最终一致，并必须具备幂等或重建路径。任何 AI 调用只能在后端完成身份认证、学校范围过滤和 Prompt 组装后发起。

## 3. 近期待办

### 阶段 A：检索评测与可观测性

1. 启动 Elasticsearch，重建存量索引并验证 create/update/delete/hide/restore 的索引收敛。
2. 配置真实 Embedding 模型，建立不少于 20 条的校园问答评测集。
3. 对比 SQL、关键词、向量和 RRF 的 TopK 命中情况。
4. 为模型调用、Embedding 和检索增加耗时、失败率、降级次数与 Token 用量指标。

### 阶段 B：问答体验

1. 助手回答的流式输出与中止能力。
2. 引用帖子卡片、可解释的检索范围和无证据提示。
3. 候选答复页的分页、折叠和多答案摘要。
4. 候选答复的 AI 辅助筛选建议。已完成：发起者可对待判断候选答复请求关联度、建议和理由；结果为临时展示，不自动采纳、不自动入库。是否采纳仍由问题发起者决定。

### 阶段 C：产品完整性

1. 通知按评论、点赞、问题追踪、关注和收藏分类。
2. “设置”入口：界面密度、语言、通知偏好与隐私偏好。
3. 校园标签跳转到校园圈，评论与答复的用户主页跳转。
4. 订阅答案中心：进行中、已完成、取消订阅与被删除提醒。

### 阶段 D：部署与求职呈现

1. Docker Compose 编排 MySQL、Redis、Elasticsearch、后端、Nginx 前端。
2. 云服务器部署，配置 HTTPS、域名、环境变量、备份和日志。
3. 补充系统架构图、API 文档、压测结果和可复现实验说明。
4. 梳理简历项目描述、核心链路讲解和面试问答。

## 4. 验收原则

每一项功能在提交前应至少具备：

1. 明确的业务规则、数据结构和权限边界。
2. 后端测试与前端构建验证。
3. 对缓存、异步事件、搜索或 AI 外部依赖的失败降级说明。
4. 一条可由用户执行的验收路径。
5. README、API 或设计文档同步更新。
