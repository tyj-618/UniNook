# 首轮项目回收结论

更新日期：2026-08-09

## 结论

CampusCircle 的核心业务链路已具备进入部署演练和作品演示准备的条件。本轮之后冻结产品范围：后续新增工作只处理阻断性缺陷、回归验收、部署和展示材料，不再调整核心数据模型或增加社交玩法。

## 已回收的交付能力

- 账号登录、短期访问令牌与 HttpOnly 刷新令牌续期；前端不再持久化访问令牌。
- 校区绑定、范围筛选、帖子、评论与二级回复、点赞、通知、个人主页。
- 问题追踪闭环：每篇帖子或每条一级评论仅允许发起一个问题，支持订阅、候选答复、发起者判断、结束、重开和通知。
- Redis 缓存、RocketMQ 异步事件、Elasticsearch 检索及 SQL 降级路径。
- Docker Compose 本地运行、Nginx 反向代理、受限健康检查、自动化验证工作流、后端自动化测试和前端构建验证。

## 本轮工程加固

- 头像上传校验实际图片格式、尺寸和像素数，并重新编码后保存，避免仅信任请求头。
- 登录失败按账号限流，并对不存在账号执行密码校验，降低暴力尝试和账号枚举风险。
- Elasticsearch 请求设置超时，故障时能更快回落到 SQL 检索。
- 容器端口默认仅绑定本机；Nginx 增加安全响应头、上传大小限制和代理超时。
- 补充生产配置模板、部署与回滚手册、冒烟脚本和演示讲解指南，覆盖环境变量、HTTPS、备份、检索服务暴露面和发布验收。

## 发布前硬门槛

以下事项完成前，不应将服务直接公开到互联网：

1. 为生产环境配置独立且高强度的数据库密码、刷新令牌密钥和模型服务密钥；不得复用示例值。
2. 使用域名与 HTTPS，并确认刷新令牌 Cookie 的 `Secure` 属性在生产环境开启。
3. 将 MySQL、Redis 和 Elasticsearch 保持在私有网络，仅由应用或反向代理访问。
4. 对生产数据库完成备份和恢复演练；按现有迁移文档核对数据库版本后再升级，禁止直接对已有数据执行未经核对的结构变更。
5. 将代码推送至托管平台后，确认 `Verify` 工作流的后端测试、前端检查和 Compose 校验全部通过。
6. 执行一次完整冒烟验收：注册/登录、选校区、发帖、评论、问题追踪、通知跳转、范围切换、助手检索和登出。

## 明确延后的需求

- 一篇帖子或一条一级评论的多问题、多面板预览与聚合交互。
- 关注、私聊、积分、收藏、复杂的回答者排序和新的社交关系模型。
- 候选答复自动采纳、自动评审、流式输出，以及非阻断性的检索模型升级。
- 大规模学校数据扩充、复杂设置中心和新的页面重构。

这些需求可以作为后续迭代素材，但不进入首轮投递前的开发范围。

## 已知运行约束

- 登录限流目前是单应用实例内存实现；横向扩容时应迁移到 Redis。
- 上传文件目前保存在应用挂载卷；正式长期运行时应迁移到对象存储并增加内容安全策略。
- 自动验证工作流已纳入仓库；首次推送后仍需确认托管平台上的实际执行结果。登录限流横向扩容和头像对象存储仍是后续演进项。

## 本轮验证记录

- `npm.cmd run lint`
- `npm.cmd run build`
- `npm.cmd audit --omit=dev --audit-level=high`：生产依赖未发现已知漏洞。
- `mvn test`：36 个测试通过。
- Docker Compose 重建后，应用、前端、MySQL、Redis 和 Elasticsearch 均正常运行。
- 浏览器刷新后仍可通过刷新令牌恢复登录态；Nginx 安全响应头已在本地入口验证。
- 发布模板、部署与回滚手册、冒烟脚本、演示讲解指南和托管平台验证工作流已加入仓库；待推送后确认首次远程执行结果。
